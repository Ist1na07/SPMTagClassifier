这是一个你即将从零开始构建的TagClassifier项目，目的是为osu!mania 7K谱面进行tag（tag一般是键型名称）分类。进一步地，一个谱面可能有很多段落（本身是连续的，需要一定的手段分开），每一个段落的键型可能比较明显干净。classifier需要正确地切分不同键型的段落和正确标注每一个段落的键型，或者说正确标注每一个位置的键型和正确聚合键型相同的段落。
技术上，4K已有的键型分类器（\osumania_estimator-main）可能参考价值很高，其使用了非机器学习方法进行键型分类。
7K的键型可能与4K有所不同，你可以参考spm map analyser（\spm_rating_map_analyser-main）的分类。这个项目中也有tag分类器的实现，但精确度非常低。
LeoBlack的map analyser（\osumania_map_analyser-main）同样有全谱面的键型综合分类器，但精确度有待提升。你可以参考。需要注意的是，我所给的这些项目似乎均没有段落切分的实现。
提供了7K谱面的数据集（\dataset），标注了300+谱面的sort和tag（后者是我们需要的）。需要注意的是：这些tag的种类（同spm map analyser）可能并不齐全；标注的是玩家对谱面的印象键型分类，这意味着当谱面存在多个不同键型时，可能没有具体的键型标注，而是标记为rc mix/ln mix/hybrid；数据不提供分段和具体分段的键型；有些简单的段落可能是一个独立键型，但由于难度低，玩家未将其标出：例如一个谱面可能大部分是很难的speed，中间有一些简单的dense chordstream，则标注可能只有speed。所有数据由人工标注且未核验，可能存在错误。
由于这个项目之前没有人完整做过，所以我特地选取了一个长的Hybrid谱面进行标注示例，放在 \TagClassifierDataset 。需要注意：标注包含自然语言注释，这些注释包括了对上一代（上一代的实现有问题，已经抛弃）算法的错误结果的指正，这些指正可以忽略。
交付物至少应包括一份完整的tosu overlay。你可以找tosu的仓库看看怎么写overlay，以及参考spm map analyser或Leoblack的map analyser，它们都是功能完整的tosu overlay。overlay应能读取当前谱面播放时间，显示当前位置的键型；类似osumania_estimator，在chordjack、chordstream等类的键型上显示具体的bpm，例如“170 Dense Chordstream”。
技术上，可以引入spm map analyser已有的组件（例如难度分析算法）辅助分析键型。例如，可以将难度偏低、键型较难判断的段落标记为Break（休息段），它们不参与整个谱面tag的判断，聚合时也可以使用时序难度作为特征。一些键型例如Release的判断也可以参考难度分析算法的实现（但需要谨慎采纳，难度分析本身也不完善）。
谱师在写谱的时候往往选择一个音乐的段落里就写一种特定的键型，因此更多时候应该是一大段一大段的键型变化。当发现有极短的独立段落时应忽略该键型，并并入前后段落。
此外，你可以选做一个附带的sort分类器，不过spm map analyser中的sort分类器准确率已经较高，该分类器也可以用作前置技术。
应该用发散性的思维和聪明的方法来思考并解决问题。
这是一个长期项目，你需要有意识地控制自己的上下文长度。例如，你可以活跃地使用子agent来做具体的任务。

附带7K各键型的解释：
RC类：这类键型由大量Rice（米饭/单点）组成。
Chordjack：大叠，特征是有大量的多押、且有轨道在连续的打击中均出现按键（重叠），且重叠较多。chord是多押的意思。
Minijack：小叠，特征是有不那么大量的多押、有重叠，且重叠较少，往往速度较快。
Dense Chordstream：大切，特征是有大量的多押，且没有重叠或重叠很少。
Fast Chordstream：速切，有一定量的多押、但少于大切，没有重叠或重叠很少，往往速度较快。
Tech：技巧，特征是节奏变化、更多地出现小叠、歪的拍（一个chord被拆成了时间不一致的打击，但打击方法仍然是当成chord打）、交互（左右手轮流发力）、锚（同一个位置连续多次等间隔出现按键），广义上除了叠、切、乱以外的RC都可以被称为tech，这里不采用广义定义。
Speed：乱，特征是多押（chord）较少、打击连续、分布于多个轨道。
Wildcard：不好分类的RC键型，没有显著的其他RC键型特征。

LN类：这类键型由大量LN（面条/长按）组成，可以包含一些RC。
Release：放手，特征是较多独立性强的面尾，有时会有较多歪（放手时间不一致）的面尾，具体可参考spm rating（即spm map analyser的难度预测算法）的release bar，该组件数值高时放手难度高。
Coordination：协调，很多时候等同于面叠（将大叠当成LN头拉成面条），特征是锁手重叠多。
Density：很多时候等同于面切（将大切当成LN头拉成面条），有时可以包含面乱（将乱当成LN头拉成面条）。
Inverse：反键，所有手指都被锁住、当有新按键时需要抬起对应手指并立即按住的键型，特征是面条拉得满、面尾到下一个按键的间隔小且相近。
Technical：很多时候等同于面技（将tech当成LN头拉成面条），特征是锁手的小叠多且不均匀、节奏变化、歪的拍、短面多。
LN Wildcard：不好分类的LN键型，没有显著的其他RC键型特征。

特殊类：
Vibro：需要用抖动发力击打的键型，往往是超高bpm的连续叠。

合成类：
RC Mix：谱面sort为RC，有不少于三个至少占有一定物量和难度的RC键型且均不占主导。
LN Mix：谱面sort为LN，有不少于三个至少占有一定物量和难度的LN键型且均不占主导。
Hybrid：谱面sort为HB，有不少于三个至少占有一定物量和难度的任意键型（Vibro除外）且均不占主导。

键型的bpm：往往指在打击间隔相等或相近的键型中，相邻两次打击的间隔等效于多少bpm的十六分音符。

一些经验：
叠是指：在相邻的两次打击中，同一轨道都出现按键的情况。宏观表现为每次打击需要完全将手按下相应的轨道，完全抬起、调整位置再按下进行下一次打击。切是指：在相邻的三次打击中，如果某一轨道在第一次打击出现按键，则在第二次打击不出现按键、第三次打击出现按键的情况。宏观表现为第一次打击按下一些相应位置的手指，第二次打击这些轨道都没有按键、其他轨道才有按键，因此不需要像叠一样整个手抬起再按下，而是只需要调整手指位置、切换到第二次打击相应的轨道。
小叠小在哪？一是叠小，二是chord小。叠小是指相邻打击的重叠少，chord小是指一次打击的押数少，很多时候甚至是单点的叠、没有chord。与tech的区分在于，tech里可以有小叠，但小叠没有tech的其他特征，例如节奏不均、有歪拍、有交互等等。再说technical，其与density的分别就像tech与chordstream的分别，另外有几个特征之前可能没提到，就是节奏不均、短LN多、排列不均匀（例如其中出现的小叠全在一块，或者从一边密集地移到另一边，不像coordination的叠那样偏均匀随机地分布）。vibro不一定是超高bpm叠，而是不太需要“控制”的抖动：叠往往各次打击会有较多的轨道变化，需要玩家每次控制好按下哪几根手指，而vibro则往往是无脑的一些轨道一直叠，不需要控制手指。dense chordstream与fast的阈值有多个参数，包括但不限于bpm（速度）、chord数，还有一个量可能有用——你可以去spm map analyser找难度分析算法里有一个跨列损失/跨列矩阵，用于支撑一个类似于切难度的分量计算，这个计算方法可能很有帮助：同样是32323的打击押数分布，有的排列方法可能对切力要求高，则被归为dense；有的排列可能对切力要求低，则被归为fast。
